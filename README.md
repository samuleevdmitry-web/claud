# Аналитика проекта

Дашборд по данным Яндекс Метрики, Вебмастера и Яндекс Карт. Сбор идёт каждый день в базу PostgreSQL;
на ней же будет работать ИИ-помощник (месячный отчёт и мониторинг). Дальше — Битрикс24 и Директ.

Сайты: oldos.ru и oldos.kz. Карты: сеть «Олдос» и Oldos Group (Алматы) — через счётчики Метрики,
которые Яндекс Бизнес создаёт для карточек.

## Запуск на ноутбуке

Нужен Docker Desktop (или Docker Engine с `docker compose`).

1. Получите код и перейдите в рабочую ветку:
   ```bash
   git clone https://github.com/samuleevdmitry-web/claud.git
   ```
   ```bash
   cd claud
   ```
   ```bash
   git checkout claude/sweet-bell-2une6f
   ```
2. Скопируйте `.env.example` в `.env` (в Windows: `copy .env.example .env`) и впишите в `.env` токен
   Яндекса в строку `YANDEX_OAUTH_TOKEN=` — как его получить, ниже. Остальные настройки уже заполнены.
3. Запустите:
   ```bash
   docker compose up -d --build
   ```
4. Откройте **http://localhost:8080**. Первые 5–10 минут сборщик загружает историю с января 2025 года,
   и дашборд пишет «Данных пока нет». Потом обновите страницу.

Дальше всё работает само: сборщик каждые 15 минут проверяет, не пора ли загрузить данные, и после 6:00
по Москве перезагружает последние дни (Метрику и Карты — за 7 дней, Вебмастер — за 30). Если ноутбук
спал или был выключен, после включения недостающие дни догрузятся. Выключенным дольше двух недель
ноутбук оставлять не стоит: аналитику запросов Вебмастер хранит только 14 дней.

| Что нужно | Команда |
|---|---|
| Посмотреть, как идёт сбор | `docker compose logs -f collector` |
| Проверить доступы к Яндексу | `docker compose exec collector python -m analytics check` |
| Обновить после изменений в коде | `git pull`, затем `docker compose up -d --build` |
| Резервная копия базы | `docker compose exec db pg_dump -U analytics analytics > backup.sql` |
| Остановить | `docker compose down` (данные сохранятся) |

Дашборд открывается только с этого ноутбука: пароля у него нет, поэтому наружу порт не открыт.

## Доступ к Метрике и Вебмастеру

Нужен OAuth-токен **только на чтение**. Пароль от аккаунта не нужен.

1. **Технический аккаунт (рекомендуется).** Заведите отдельный Яндекс ID, например
   `analytics-bot@yandex.ru`. В Метрике: *Настройка счётчика → Доступ → Добавить пользователя*,
   логин технического аккаунта, права «Только просмотр». Если позже подключаем Вебмастер, там
   же: *Настройки → Права доступа*, делегировать права этому логину.
2. **Приложение.** Под техническим аккаунтом откройте https://oauth.yandex.ru/client/new:
   - название — любое, например «Дашборд аналитики»;
   - платформа — «Веб-сервисы», Redirect URI — `https://oauth.yandex.ru/verification_code`;
   - доступы: **Яндекс Метрика → получение статистики, чтение параметров своих и доверенных
     счётчиков** (`metrika:read`), **Яндекс Вебмастер** — `webmaster:hostinfo` и `webmaster:verify`.
     Второе право Вебмастера, несмотря на название, нужно и для чтения данных о сайте: без него API
     отдаёт только список сайтов.

   После создания скопируйте **ClientID**.
3. **Токен.** Под тем же техническим аккаунтом откройте
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` и нажмите
   «Разрешить». На странице появится токен.
4. Положите токен в `.env` в строку `YANDEX_OAUTH_TOKEN=`. Файл `.env` не попадает в git; не пересылайте
   токен в чатах.

   В облачной сессии Claude Code токен хранится как секрет окружения: прокси сам добавляет
   заголовок `Authorization: OAuth <токен>` к запросам на `api-metrika.yandex.net` и
   `api.webmaster.yandex.net`. Тогда `YANDEX_OAUTH_TOKEN` оставляют пустым, и сборщик
   отправляет запросы без своего заголовка.

По документации Вебмастера токен действует 6 месяцев, потом его нужно перевыпустить (шаг 3).

Для данных Карт аккаунт токена должен видеть счётчик карточки в Метрике. Такой доступ выдаётся не в
Метрике, а через Яндекс Бизнес: его получают представители организации.

Отозвать доступ можно в любой момент: удалить технический аккаунт из доступов счётчика или
отозвать доступ приложения в настройках безопасности Яндекс ID.

## Команды

Внутри Docker — через `docker compose exec collector python -m analytics <команда>`.

| Команда | Что делает |
|---|---|
| `check` | Проверяет доступы: счётчики и их цели, сайты Вебмастера |
| `sync [--since ГГГГ-ММ-ДД]` | Загружает все настроенные источники (по умолчанию — последние дни) |
| `sync-metrika`, `sync-maps`, `sync-webmaster` | То же для одного источника |
| `schedule` | Ежедневный сбор в бесконечном цикле (так работает контейнер `collector`) |
| `init-db` | Создаёт или обновляет таблицы и представления |

Настройки — в `.env` (описание каждой строки — в `.env.example`). ID целей-заявок пишутся в
`METRIKA_LEAD_GOALS`, их список выводит `check`.

## Данные

| Объект | Что в нём |
|---|---|
| `metrika_traffic` | Визиты, посетители, отказы, глубина, время по дням и месяцам в срезах `total`, `source`, `utm`, `city`, `device` |
| `metrika_goal_stats` | Достижения целей в тех же срезах |
| `metrika_goals` | Цели счётчика и отметка «заявка» |
| `metrika_kpi` | Трафик + заявки + конверсия для любого среза |
| `metrika_monthly` | Месяц к прошлому месяцу и к тому же месяцу год назад |
| `webmaster_search_daily` | Показы, клики и средние позиции в поиске Яндекса по дням |
| `webmaster_queries_monthly` | Популярные запросы за месяц |
| `webmaster_query_daily` | Запросы по дням: показы, клики, позиция, спрос, главная страница |
| `webmaster_sqi`, `webmaster_pages_in_search`, `webmaster_crawl_daily` | ИКС, страницы в поиске, обход роботом |
| `webmaster_summary`, `webmaster_diagnostics` | Сводка сайта и проблемы из диагностики |
| `webmaster_search_monthly` | Поиск по месяцам с прошлым месяцем |
| `webmaster_position_buckets` | Показы по диапазонам позиций |
| `webmaster_freshness` | Насколько отстают данные Вебмастера |
| `metrika_counters` | Счётчики: сайт или карточка на Картах |
| `maps_monthly` | Карточка на Картах по месяцам: визиты, звонки, маршруты, переходы на сайт |
| `metrika_contacts` | Клики по телефону, почте и мессенджерам |
| `sync_runs` | Журнал запусков сборщиков |

Формулы показателей — в [docs/metrics.md](docs/metrics.md).

# Velmorium — мониторинг тендеров на гостиничный текстиль

Веб-приложение обходит тендерные площадки, находит закупки по ключевым словам из файла
`Velmorium_ключевые_слова_тендеры.xlsx` и раскладывает их по статусам
«Релевантный» / «На проверку» / «Отклонён». Приложение запускается на вашем компьютере:
российский IP нужен, чтобы площадки его пускали.

Готово: разведка площадок (`docs/sources.md`), ключевые слова и классификатор, адаптеры
**ЕИС через ГосПлан API** и **Online Contract**, сохранение с дедупликацией, прогон с журналом
и сигнализацией о сбоях, приём данных от **Claude in Chrome** (`docs/claude_in_chrome.md`).
Дальше: список тендеров и карточка в интерфейсе, планировщик, адаптеры остальных площадок.

## Запуск через Docker (рекомендуется)

Нужен Docker Desktop.

```bash
git clone <репозиторий> && cd claud
cp .env.example .env      # задайте APP_PASSWORD
docker compose up -d --build
```

Приложение: http://127.0.0.1:8000 (логин `velmorium`, пароль из `.env`). База — PostgreSQL в
контейнере `db`, данные сохраняются между перезапусками.

Команды внутри контейнера:

```bash
docker compose exec app python -m app.cli run              # прогон по всем площадкам сейчас
docker compose exec app python -m app.cli probe            # разведка площадок (см. ниже)
```

## Запуск без Docker

Нужен Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
# в .env: DATABASE_URL=sqlite:///./data/app.db
uv run uvicorn app.main:app            # http://127.0.0.1:8000
uv run python -m app.cli run           # прогон сейчас
```

При старте применяются миграции, а если в БД нет ключевых слов — импортируется файл из корня.

## Площадки

| Режим | Площадки |
|---|---|
| Автоматически (адаптер) | ЕИС через ГосПлан API, Online Contract |
| Claude in Chrome → «Импорт» | Bidzaar (капча), ТЭК-Торг (антибот), ЭТП УГМК |
| Адаптер в работе | ЕИС напрямую, РТС-тендер, Сбербанк-АСТ, Росэлторг, ЭТП ГПБ, Фабрикант, B2B-Center, Tender.Pro, OTC.ru, ЭТП НИТ |

**Разведка с вашего компьютера.** Отсюда разработчику площадки из последней строки недоступны.
Запустите один раз:

```bash
python -m app.cli probe        # или: docker compose exec app python -m app.cli probe
```

Команда делает по 2–4 запроса на площадку с паузами, ничего не обходит и сохраняет ответы
в архив `data/probe/<дата>.zip`. Пришлите архив — по нему пишутся адаптеры и тесты.

**ГосПлан.** Без ключа используется тестовый сервер (10 запросов в минуту — полный прогон идёт
долго). Ключ для продуктового сервера: Telegram-бот «Бот ГосПлан», 7 дней бесплатно, далее
3 000 ₽/мес. Укажите его в `.env` как `GOSPLAN_API_KEY`. Когда заработает прямой адаптер ЕИС,
ГосПлан можно будет отключить.

## Ключевые слова

Файл xlsx — единственный источник ключей. Новую версию загружают на странице
«Ключевые слова»: предпросмотр разбора масок с ошибками, затем применение; после применения
все сохранённые тендеры пересчитываются. Там же можно проверить классификацию на тексте.

Синтаксис масок: `*` — любое окончание, `|` — «или», скобки группируют варианты, слова подряд —
фраза (между словами не больше двух других слов), дефис или `/` внутри слова — части идут
строго подряд (`мини-отел*`, `спа-*`), `[её]` — один символ из набора. Сравнение без учёта
регистра, `ё = е`, кавычки и дефисы игнорируются, совпадение только по целым словам
(`отел*` не находит «отдел»). Основа на «согласный + к/ц» перед `*` ловит и форму с беглой
гласной: `подушк*` → «подушек» (отключается `MASK_FLEETING_VOWELS=false`).

Поисковые запросы к площадкам строятся из файла: все «Самодостаточные» ключи, ключи
«Нужен маркер» с приоритетом 1–2 и «Готовые запросы» типа «Без логики». Для ЕИС
дополнительно ищется по кодам ОКПД2/КТРУ (кроме кодов-исключений).

## Командная строка

```bash
python -m app.cli check-keywords [файл.xlsx] [--notes]   # разобрать файл ключей
python -m app.cli classify "Поставка полотенец" --customer "Санаторий «Дюны»"
python -m app.cli run [--source eis_gosplan] [--query "постельное белье"]
python -m app.cli probe [--source eis]
```

## Как добавить площадку

1. Снять реальные ответы (`probe` или вручную) и положить в `tests/fixtures/<код>/`.
2. Написать адаптер в `app/sources/<код>.py` с методами `search`, `fetch_details`,
   `healthcheck` (см. `app/sources/base.py`) и использовать `PoliteClient` — он держит паузы,
   повторяет при 429/5xx и распознаёт капчу и антибот.
3. Добавить площадку в `app/sources/registry.py` с `mode="api"` и фабрикой адаптера.
4. Написать тесты парсинга на фикстурах (`tests/test_sources.py`).
